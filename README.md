# Умник AI

AI-пространство на Next.js и TypeScript: чат Umik.6 на модели GPT-6 Luna от OpenAI и творческая студия для изображений и видео через fal.ai.

## Возможности

- Единый чат Umik.6 на модели GPT-6 Luna от OpenAI
- Творческая студия: генерация изображений и видео — до 20 изображений и 10 видео на пользователя за календарный месяц после настройки Supabase; подтверждённый аккаунт разработчика из allowlist не расходует лимит приложения.
- `/artifacts`: редактор HTML/CSS/JS с изолированным предпросмотром, редактор TypeScript и Markdown; копирование и скачивание файлов.
- Выбор формата изображения/видео, просмотр результата и галерея последних 30 работ в локальном браузере
- Светлая/тёмная/автоматическая тема и выбор языка интерфейса
- Ключи API используются только на сервере

## Локальный запуск

1. Установи Node.js 20 или новее.
2. Выполни `npm install`.
3. Скопируй `.env.example` в `.env.local`.
4. Добавь `OPENAI_API_KEY` из [OpenAI API Platform](https://platform.openai.com/api-keys). Ключ используется только на сервере. Для изображений/видео добавь `FAL_KEY` из https://fal.ai/dashboard/keys.
5. Запусти `npm run dev` и открой http://localhost:3000. Студия доступна по адресу http://localhost:3000/studio, артефакты — http://localhost:3000/artifacts.

## Переменные окружения

- `OPENAI_API_KEY` — чат Umik.6 на GPT-6 Luna от OpenAI. Храни ключ только в серверных переменных окружения.
- `FAL_KEY` — генерация изображений и видео. Без этого ключа студия покажет понятное сообщение о настройке.
- `FAL_IMAGE_MODEL` — необязательная модель изображений; по умолчанию `fal-ai/flux/schnell`.
- `FAL_VIDEO_MODEL` — необязательная модель видео; по умолчанию `fal-ai/wan/v2.2-a14b/text-to-video`.
- `UMNIK_OWNER_EMAILS` — список email подтверждённых аккаунтов разработчика через запятую; хранится только на сервере. Не отменяет стоимость API у провайдера.

## Важно

Генерация использует платный/квотируемый API-аккаунт fal.ai и может расходовать баланс. Условия и доступность конкретных моделей зависят от аккаунта и провайдера. Галерея хранится в localStorage текущего браузера; это не облачное хранилище. Ссылки на файлы выдаёт провайдер, поэтому скачивай нужные результаты, чтобы сохранить их надолго. Не публикуй API-ключи в репозитории.


## Аккаунты, подтверждение почты и сохранение чатов

Для реального входа создай проект в [Supabase](https://supabase.com/dashboard) и добавь в переменные окружения сайта:
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

Затем выполни SQL из `supabase/schema.sql` в Supabase → SQL Editor. Он создаёт таблицу истории чатов, месячные счётчики генераций и политики Row Level Security. Для лимитов генерации также нужен `SUPABASE_SERVICE_ROLE_KEY` только на сервере. Генерация требует входа в аккаунт; запросы резервируют лимит перед запуском у провайдера, поэтому неудачная задача может расходовать попытку.

В Supabase → Authentication → Sign In / Providers:
1. Включи Email и настрой шаблон письма так, чтобы в нём был код `{{ .Token }}`. Для стабильной доставки всем почтовым доменам подключи собственный SMTP-провайдер и подтверди домен отправителя; стандартные лимиты Supabase могут быть ограничены.
2. Включи Google и укажи OAuth Client ID/Secret из Google Cloud Console.
3. Включи Apple и укажи Service ID, Team ID, Key ID и private key из Apple Developer.
4. Добавь адрес сайта и callback `https://ТВОЙ-ДОМЕН/auth/callback` в разрешённые redirect URLs и в настройки каждого OAuth-провайдера.

После публикации добавь те же Supabase-переменные в хостинг (например, Vercel) и запусти redeploy. Email-коды, Google и Apple не заработают только от наличия кода в репозитории: нужны реальные настройки и учётные данные провайдеров. История чата в облаке сохраняется после входа; если таблица ещё не создана, чат продолжит работать, но облачная история будет недоступна.

## Платные тарифы и банковская карта (Stripe)

Добавлена страница `/pricing`, серверный Checkout и проверка подписи Stripe webhook. Реальные платежи требуют настройки аккаунта Stripe, цен, секретов и webhook. Карточные данные вводятся на защищённой странице Stripe, а не сохраняются этим сайтом.

Чтобы включить оплату:
1. Создай Stripe account и три recurring EUR prices: 5 € каждую неделю, 15 € каждый месяц, 50 € каждый год.
2. В настройки хостинга добавь `STRIPE_SECRET_KEY`, `STRIPE_PRICE_WEEKLY`, `STRIPE_PRICE_MONTHLY`, `STRIPE_PRICE_YEARLY`, `STRIPE_WEBHOOK_SECRET`, `NEXT_PUBLIC_SITE_URL`.
3. В Stripe Dashboard → Settings → Payment methods включи карточные платежи и доступные цифровые кошельки. Checkout не передаёт фиксированный список `payment_method_types`: Stripe динамически выбирает подходящие способы оплаты, включая Apple Pay и Google Pay, когда они доступны для страны, валюты, устройства и аккаунта. Не добавляй жёсткий список методов в код — он может скрыть другие варианты.
4. Добавь `SUPABASE_SERVICE_ROLE_KEY` только как серверную переменную (никогда не используй префикс `NEXT_PUBLIC_` для service-role key).
5. Выполни обновлённый `supabase/schema.sql` в Supabase SQL Editor.
6. В Stripe добавь webhook endpoint `https://ТВОЙ-ДОМЕН/api/billing/webhook` и все нужные события подписки и счетов, включая неудачные платежи и возвраты. Скопируй signing secret в `STRIPE_WEBHOOK_SECRET`.
7. Проверь платежи в Stripe test mode на разных устройствах и браузерах до включения live mode.

Stripe принимает основные карточные бренды, но доступность конкретной карты зависит от страны, бренда, банка-эмитента и ограничений аккаунта. Apple Pay появляется на поддерживаемых устройствах/браузерах, если кошелёк настроен и Stripe считает его подходящим для платежа; гарантировать абсолютно все карты невозможно. Тарифы создают повторяющиеся подписки, а не разовые покупки. Перед запуском определи лимиты использования, условия отмены/возврата, налоги и обязательную информацию для потребителей. Для несовершеннолетнего владельца аккаунта настройку платёжного аккаунта и реальные платежи должен проводить родитель/опекун с учётом правил Stripe и местного законодательства.

**Важно:** страница и серверная интеграция подготовлены, но пока не подключены реальные Stripe price IDs и секреты. До настройки webhook оплата не активна. Система подписок пока не блокирует/не увеличивает лимиты чата автоматически; это отдельный шаг, который нужно реализовать и протестировать до продажи платного доступа.
